# Security and Governance Principles

Founder Repo OS is designed to make repository change more deliberate and reviewable for AI-assisted development.

## Reviewable change

- Proposed files are visible before a repository write is requested.
- A full diff is part of the review path.
- Repository changes are prepared through a dedicated branch and Draft Pull Request.
- The repository owner retains the explicit merge decision.

## Clear operating boundaries

- Repository-specific rules help make expected AI-agent behavior visible.
- Governance and handoff material is designed to clarify ownership and review expectations.
- Customer repository scope is tied to the plan and the repository choices the customer authorizes.

## Maintained foundation

An active Founder Repo OS subscription includes relevant product maintenance updates to the supported operating foundation, including relevant governance, AI-agent boundary, review or release workflow, and compatibility updates when published.

## Important limits

Founder Repo OS does not guarantee security outcomes, prevent all vulnerabilities, replace GitHub security features, replace professional security reviews, or provide continuous monitoring. Customers should review proposed changes and maintain their own repository, security, legal, and deployment controls.
